个人站做 AI 功能，绕不开一个问题：**API Key 放在哪。**

## 方案一：纯前端直连

```ts
await fetch("https://api.openai.com/v1/chat/completions", {
  headers: { Authorization: `Bearer ${localStorage.getItem("key")}` },
});
```

- 优点：零基建，用户自己填 Key，站长不承担费用
- 缺点：跨域限制、Key 暴露在前端、无法做限流和内容审核
- 适合：**只给自己用**的工具

## 方案二：服务端代理

浏览器只和你的 `/api/ai/chat` 说话，Key 留在服务器环境变量里。

- 优点：可以限流、可以记录、可以换模型不改前端
- 缺点：你要为所有人付费，还要防滥用
- 适合：**有明确用户群**的小站点

## 方案三：混合 + 演示模式

这是块集目前的做法：

1. 服务端代理优先，Key 从环境变量读；
2. 没有 Key 时，接口不报错，进入**演示模式**，返回预先写好的示例回复，并在界面上明确标注；
3. 用户可以在本地设置里填自己的 Key，走自己的额度。

```ts
const configured = Boolean(process.env.OPENAI_API_KEY);
if (!configured) return demoReply(prompt);
```

## 为什么"演示模式"值得做

它是**空项目的第一次访问体验**：

- 访客点进来，页面能完整走通，不会看到一堆红色报错
- 你自己部署时，不用先掏钱就能验收 UI 和交互
- 演示模式下界面有醒目标注，不会误导别人以为能用

> 一个功能"没有Key时也能体面地失败"，比"配置齐全时很强大"更能体现工程质量。

## 成本控制的三条土办法

1. 按 IP 做每日次数上限；
2. 对话只保留最近 12 条上下文，不做无限历史；
3. 图片生成单独限额，因为它比文本贵一个量级。

这些都不优雅，但对个人站足够。
