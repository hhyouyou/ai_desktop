# 上线前合规与风险清单

> 本文针对「做一个工具箱 + AI + 热点聚合类站点」的真实风险，按中国境内面向公众运营的场景整理。
> 不是法律意见。上线前请按你的实际主体、部署地和功能范围逐条确认。

## 0. 与参考站点的关系

| 项目 | 结论 |
|---|---|
| 参考站点源码 | **未开源**。其 GitHub 账号下没有站点仓库，搜索 `ttkit.cn` 无结果；仅部分周边服务开源（daily-hot-api、todo-done 等，MIT） |
| 本站代码 | 全部自研，未复制任何第三方代码、素材、文案 |
| 本站名称/Logo | 「块集 BlockSet」为独立命名与自绘 Logo，与参考站点无关联 |
| 功能相似是否侵权 | 功能与交互模式一般不受著作权保护；受保护的是具体代码、文案、图片、商标。已避开 |

**不要做的事**：使用对方名称、Logo、备案号；逐字复制对方文案或博客；镜像/反代对方站点；抓取其站内数据。

## 1. 知识产权

- [x] 代码自研，未引入无 License 的第三方代码
- [x] 图标、插图为手写 SVG，无外部素材
- [ ] 若后续引入字体/图片素材：确认商用授权（本站当前只用系统字体，无此风险）
- [ ] 若使用开源组件：保留原 LICENSE 与版权声明（本项目依赖均为 MIT/Apache-2.0）

## 2. 名称与商标

- [ ] 上线前做商标近似检索（中国商标网），确认「块集 / BlockSet」在 9 类、42 类可注册
- [ ] 域名、公众号、小程序名称一并检索，避免与在先权利冲突
- [ ] 不要在宣传中使用他人品牌名做对比营销

## 3. ICP 备案（境内服务器）

- [ ] 80/443 端口对外提供服务，必须完成 ICP 备案（个人或企业主体）
- [ ] 个人备案不得用于经营性内容；工具箱/AI 类目建议用企业主体
- [ ] 备案信息与页脚展示一致；不能借用他人备案号
- [ ] 若部署在境外（Vercel 等），理论上无需备案，但境内访问速度与合规提示需自行评估

## 4. 生成式 AI 合规

依据《生成式人工智能服务管理暂行办法》（2023-08-15 施行）与《人工智能生成合成内容标识办法》（2025-09-01 施行）：

- [ ] 面向境内公众**提供**生成式 AI 服务（自己部署模型或代理对外提供）→ 需履行备案/安全评估
- [ ] 仅调用**已备案**的第三方模型 API（DeepSeek、通义、豆包等）且自己不做模型服务 → 风险显著降低，但仍需内容安全
- [ ] AI 生成的文字/图片必须有**显式标识**（界面注明「AI 生成」）与隐式标识（元数据）—— 本站已做界面标注
- [ ] 需要有违法有害内容过滤与投诉举报入口
- [ ] 未成年人保护：不提供可能诱导沉迷或不适龄的内容

## 5. 热点数据来源

- [ ] 抓取微博/知乎/百度/抖音等热榜，可能违反来源站《用户协议》与 robots 协议
- [ ] 热榜标题属于他人内容，聚合展示存在著作权与不正当竞争风险
- [ ] 推荐做法：使用有授权的数据 API；或只展示标题+外链并注明来源，不缓存全文
- [ ] 本站当前默认使用**示例数据**并在界面标注，正式接入前必须解决授权问题
- [ ] 开源项目 daily-hot-api（MIT）可用，但其数据来源合规责任仍在使用者
- [x] 当前实现：本地部署 DailyHotApi（MIT）+ 3 个原生适配器抓取各平台公开接口，
      仅作技术演示与自用；微博等平台存在反爬（无 Cookie 返回 432），随时可能失效
- [ ] 若对外运营：优先换取数据授权，或只保留「标题 + 原文外链」并显著标注来源

## 6. 个人信息保护

- [ ] 收集邮箱/昵称 → 需有隐私政策、告知同意、最小必要原则
- [ ] 匿名身份由 IP+UA 哈希派生，属于去标识化处理，仍建议在隐私政策中说明
- [ ] 提供账号注销与数据删除入口
- [ ] Cookie 使用需告知（本站 cookie 仅用于登录会话签名）
- [ ] 不要记录与业务无关的敏感信息

## 7. 广告、支付与赞赏

- [ ] 个人站直接挂收款码在部分渠道属违规，建议走合规赞赏平台或暂不开放
- [ ] 投放广告需办理相应资质/备案，且不得为违规内容导流
- [ ] 不做「付费解锁工具」等可能被认定为经营性互联网信息服务的设计

## 8. 免责与声明

页面上至少要有：

- [ ] 站点为个人/独立项目，与任何第三方无关的声明
- [ ] 示例数据、演示模式的明确标注
- [ ] AI 输出不构成事实判断或专业建议的提示
- [ ] 外部链接的内容由目标站点负责的声明

## 9. 技术与安全

- [ ] `SESSION_SECRET` 必须替换为随机值，不得使用仓库默认值
- [ ] API Key 只放服务端环境变量；前端填写只存 localStorage
- [ ] AI 接口做频率限制（按 IP / 按天），防止被刷爆额度
- [ ] 上传能力（当前无）若后续增加，需限制类型/大小并做病毒扫描
- [ ] 依赖定期 `npm audit`；SQLite 定期备份

## 10. 上线检查表（最短路径）

1. 换取新 `SESSION_SECRET`，配置 `.env`
2. 补全页脚主体信息 + 隐私政策 + 用户协议页面
3. 完成 ICP 备案（境内）或确认境外部署策略
4. 决定 AI 形态：**只做演示模式** → 合规成本最低；接第三方 API → 加内容过滤 + AI 标识；自建模型对外提供 → 走备案流程
5. 热点模块接入有授权的数据源，或保持「示例数据 + 外链」形态
6. 加 rate limit、错误监控、每日备份
7. 准备投诉/举报联系方式

---

**给个人项目的一句话建议**：先把「不承诺实时性、不承诺 AI 准确性、不收集多余数据」写进界面，
合规压力和运营风险都会小一个量级。
